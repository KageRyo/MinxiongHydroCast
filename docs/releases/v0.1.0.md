# v0.1.0 — Observation Service

MinxiongHydroCast v0.1.0 establishes the first supported product boundary: a localhost-only,
official-source hydrometeorological observation service for Minxiong/Chiayi, with reproducible
research interfaces kept behind explicit publication gates.

Release date: 2026-07-29

## Highlights

- Collects and validates CWA `O-A0002-001` rain gauges, WRA active rainfall warnings, and WRA IoW
  flood-sensor measurement/catalog snapshots.
- Handles transient empty bodies, invalid JSON, repeated pages, malformed pages, and changing WRA
  join transactions with bounded retry and structured retry telemetry.
- Persists immutable snapshots with strict schemas, health/readiness state, provenance, redacted
  source URLs, and SHA-256 checksums.
- Exposes a read-only API, localhost operator view, health/readiness endpoints, Prometheus metrics,
  verified backup/restore, and rolling shadow evaluation.
- Preserves degraded scraper behavior without treating fallback data as ready or masking schema
  drift.
- Includes continuous radar-event discovery, a read-only human-review queue, reproducible event
  splits, Persistence evaluation, and a weighted Tiny U-Net research baseline.
- Keeps forecast publication unavailable because the learned baseline does not consistently pass
  CSI and lead-time promotion gates.

## Verified release evidence

- Python compilation, Ruff, and the complete test suite pass.
- CI covers Python 3.11 and 3.13; CodeQL provides static security analysis.
- A real live operator view was captured on 2026-07-29 with a healthy observation snapshot.
- The same dated rolling window had 1,150 live attempts, 99.39% collection success, and 97.39%
  readiness.
- The shadow gate remained blocked by a 50.98-minute maximum gap and no confirmed heavy-rain
  period. Automated notification remained disabled.
- Formal independent evaluation used one validation and two held-out local test events. Tiny U-Net
  improved aggregate RMSE on all three but regressed CSI on one local event and some lead times.

## Public package boundary

The release contains code, schemas, deployment templates, synthetic samples, aggregate results,
and a model card. It does not contain:

- CWA/WRA credentials or Discord webhook URLs;
- live snapshots, backup archives, logs, or host-specific configuration;
- official raw radar/QPE downloads or short-retention event evidence;
- CCTV, unpublished flood labels, model checkpoints, or trained weights.

The MIT license applies to repository code only. Official data and any future trained-weight
distribution require separate rights review.

## Upgrade and use

Install from the tag:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install "git+https://github.com/KageRyo/MinxiongHydroCast.git@v0.1.0"
mhc operations --mode demo --once
mhc serve --host 127.0.0.1 --port 8080
```

For live collection, copy `env.example` to an ignored `.env`, add credentials locally, and follow
[operational use](../operational_use.md). For the managed single-host profile, choose a durable
root explicitly and follow the [runbook](../single_host_operations.md).

## Known limitations

- Not an official warning system or public emergency service.
- Public forecast and automated risk notification are disabled.
- The research split is too small for broad weather-regime claims.
- QPE/gauge validation and reviewed local flood labels are incomplete.
- Public ingress, remote backup, on-call ownership, and incident exercises are deployment-owner
  responsibilities.
