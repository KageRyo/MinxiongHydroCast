# v0.2 Dataset Protocol

`v0.2.0` is a reproducible radar-dataset milestone, not a forecast-release milestone. The
repository publishes contracts, manifests, synthetic fixtures, validation code, and aggregate
results. Raw CWA/WRA captures, generated tensors, private review catalogs, checkpoints, credentials,
and deployment paths remain outside Git.

## Tracked release inputs

The public protocol is composed of these versioned files:

| Concern | Tracked contract | Boundary |
| --- | --- | --- |
| Formal event IDs, timestamps, source, and split membership | `data/samples/event_split_manifest.json` | Strict Pydantic schema `2.0`; event-based `2/1/2` minimum split |
| Candidate discovery and weather-context status | `data/samples/radar_event_windows.json`, `data/samples/event_weather_context.json` | Radar-only candidates stay `official_context_pending` until official evidence is reviewed |
| Official source and redistribution notes | `data/samples/weather_context_source_review.json`, `docs/data_source_register.md` | URLs and aggregate status only; no raw evidence |
| QPE/gauge availability | `data/samples/qpe_gauge_validation_status.json` | A blocked QPE history probe is not a validation result |
| Tensor shape, cadence, units, CRS, masks, and normalization | `docs/radar_tensor_conversion.md`, `docs/data_assets.md` | Generated tensor archives and train-only statistics stay external |
| Artifact checksums, frame availability, metrics, and build provenance | External `dataset_catalog.json` and `dataset_verification.json` | Paths are relative to the configured data root and are never committed |

The event split manifest has a companion SHA-256 file,
`data/samples/event_split_manifest.json.sha256`. The public-contract validator checks the bytes
before validating the strict schema, so an unreviewed edit or schema drift fails closed in CI.

## Reproduce the credential-free contract checks

From a clean checkout:

```bash
python scripts/validate_public_contracts.py
python -m pytest -q \
  tests/test_event_splits.py \
  tests/test_dataset_build.py \
  tests/test_qpe_gauge_validation.py
```

These checks validate the fixed split and rebuild the tensor/archive logic with synthetic fixtures;
they do not download official data. The complete external build is intentionally separate:

```bash
mhc dataset build \
  --manifest data/samples/event_split_manifest.json \
  --root "$MINXIONGHYDROCAST_DATA_ROOT" \
  --skip-download
```

Use `--skip-download` only when the external root already contains a complete collection. A clean
build normally downloads the CWA history index and event frames, validates cadence/grid metadata,
creates sliding windows, evaluates Persistence and Optical Flow, optionally trains Tiny U-Net, and
writes a checksummed external catalog. The build must fail before training when the manifest, source
artifacts, candidate review, or checksums do not satisfy their contracts.

## Review and evidence gates

The current five-event benchmark remains the formal development split. It is deliberately retained
as a fixed comparison point while the private discovery catalog accumulates reviewed events. A
candidate can enter a future split only after all of the following are available:

1. complete cadence-aligned radar frames and immutable checksums;
2. an explicit human review decision and weather regime;
3. synchronized QPE, gauge, and warning evidence where the source contract requires it;
4. official weather context with a redistribution-safe provenance record; and
5. a separately reviewed manifest change followed by a new catalog and unchanged model gates.

Discovery never edits the formal manifest. Radar threshold crossings are not weather-type labels,
and QPE is an estimate that must be checked against gauges. The QPE/gauge validator accepts both
raw CWA-style station payloads and the repository's normalized `rain_gauges` records so collected
candidate evidence can be audited without treating it as ground truth.

## Current status and publication boundary

As of 2026-09-12, the formal five-event manifest is valid and checksum-pinned, but official weather
context and event-time QPE/gauge reports are incomplete for the formal split. The weighted Tiny
U-Net comparison therefore remains a research result with `forecast_publication_ready=false`.
The private review queue has 128 candidates: 1 approved `convective`, 2 rejected/unclassified, and
125 pending; no `typhoon`, `frontal`, or `mei_yu` candidate has been approved, and none of these
candidate decisions changes formal split membership. These are aggregate counts only; candidate
artifacts and reviewer records remain outside the public repository.
This protocol is suitable for archival and citation of the data-building method; it does not imply
operational forecast readiness or authorize external alerts.
